## P0：先确认的产品决策

- [ ] 明确首页主交互是“路线优先”还是“节点内容优先”
  当前意见同时要求“点击节点看分享”和“点击路线直接进入现成玩法”，需要先定主入口与次入口
- [ ] 明确 `Explore` 页是否保留底部弹窗
  原始意见里同时出现“路线直接可点击后也许不需要下面弹窗”和“可以保留”两种方向
- [ ] 明确 `Profile` 页的定位
  是以“个人足迹资产库”为主，还是改成更接近“小红书主页”的旅行档案 feed
- [ ] 明确“博主主页”和“我的主页”是否共用同一套资料结构
  若需要支持浏览他人主页、头像跳转、路线归档，就要先统一用户档案模型
- [ ] 明确“热门路线颜色变化”的指标口径
  需要定义按浏览量、收藏量、实际行走次数还是内容投稿频率来决定路线热度

## Profile / 我的

- [x] 把当前“我的”页增强为“旅行档案库”
  每次真实旅行可自动形成一个档案；用户自己规划并执行的路线也可手动生成档案
- [ ] 为旅行档案增加“帖子式封面”
  支持封面图、标题、副标题、地区、时间范围等基础信息
- [ ] 为旅行档案封面加入“路线签名”
  在封面角落增加简化路线线条或路线徽记，形成更稳定的视觉识别
- [ ] 增加个人资料编辑入口
  点击头像进入个人资料页，支持修改昵称、头像、简介等基础信息
- [ ] 评估 `Timeline / Atlas / Poster` 三种现有视图是否需要合并到“旅行档案 feed”
  若改版，应明确现有足迹统计入口放在页面顶部、二级页还是档案详情页

## Explore / 首页探索

- [ ] 重做 Spot 弹窗的信息结构
  从“单个地点详情”升级为“同一地点下不同用户内容流”
- [ ] 将 Spot 弹窗改为“博主内容卡片”样式
  每张内容卡包含头像、照片、地点标记；左右滑动切换同一节点下不同用户的内容
- [ ] 打通“从 Spot 内容进入博主主页”
  点击头像可查看该用户在包含该节点的路线里还去过哪些地方
- [ ] 支持从 Spot 内容或博主主页快速收藏节点
  让用户从浏览内容直接进入 `Wishlist`，减少跨页操作
- [ ] 设计“长按节点快速规划”交互
  长按节点后弹出简化版待规划列表或快捷操作层，支持快速加入当前路线草稿
- [ ] 设计“热门路线”图层或筛选
  地图上允许直接选择已有路线，并通过颜色或样式表达热度差异
- [ ] 约束热度机制，避免只放大热门点位
  需要保留小众景点的可见性，例如加入“编辑精选 / 新发现 / 小众路线”并行入口

## Plan / 规划

- [x] 强化 Wishlist 的“自动归类”
  目标是解决“收藏后吃灰”，按地点自动聚合为城市 / 省份 / 地区层级
- [ ] 为 Wishlist 增加“从内容到路线”的转化入口
  用户从首页看内容时，可直接把节点加入已有路线草稿或创建新路线
- [ ] 引入 AI 路线规划助手
  基于已收藏点位、时间窗口、出发地等条件，自动生成建议路线
- [ ] 增加行程变更时的替代点位推荐
  例如迟到、闭店、天气变化时，给出附近替代节点或顺序重排建议

## Tracker / 记录

- [ ] 降低记录门槛，减少主动录入
  优先让用户通过照片导入和轨迹回收完成记录，而不是强依赖手动填写
- [x] 把照片 EXIF 导入作为主入口之一
  重点支持苹果照片中的时间与位置信息解析，减少重复输入
- [ ] 评估“记录”能力是否部分并入 `Profile`
  原始意见更倾向于让照片聚类结果直接沉淀为旅行档案内容，而不是单独停留在工具页

## 数据与实现支撑

- [ ] 补充“用户内容”数据模型
  现有数据更偏 `Way / Spot / TrackSession`，后续需要新增用户主页、Spot 投稿、旅行档案等模型
- [ ] 明确旅行档案的生成规则
  自动生成基于真实轨迹，手动生成基于用户规划路线，两者的数据来源和状态需要区分
- [ ] 为 Spot 内容流定义最小接口
  至少要明确：发布者、照片、拍摄时间、地点、所属路线、可见性
- [ ] 明确 EXIF 导入的权限与隐私边界
  需要提前定义是否默认读取地理信息、是否允许用户删除坐标、是否只在本地处理

## 建议实施顺序

1. 先完成 `P0` 产品决策，避免 `Explore` 与 `Profile` 方向反复
2. 第二步做 `Profile` 信息架构重构，因为它影响“旅行档案”是否成为核心对象
3. 第三步重做 `Explore` 的 Spot 内容流与博主主页跳转
4. 第四步补 `Plan` 的自动归类与内容转路线能力
5. 最后再把 `Tracker` 的 EXIF 导入和自动归档能力接到真实数据流
